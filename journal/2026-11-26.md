# EveryBox Journal — 2026-11-26

## Full Attachment Support (Composer & Reading Pane), Cc/Bcc Display & Draft Indicators
### Context
In live testing, Gmail drafts that had PDF attachments showed no attachments when opened in EveryBox's Composer, attachments couldn't be opened by clicking them in either the Composer or the Reading Pane, and unsent draft replies inside Inbox threads were easy to miss. Also, an old Gmail Template appeared in VantageBP Drafts because Google's Gmail API stores Canned Responses / Templates as drafts with no distinguishing flag.

### Discussion
- Wired `attachments` through `openComposer`, `Composer.tsx`, `ThreadReader.tsx`, `main/index.ts`, `preload/index.ts`, `gmail-sync.ts`, `imap-sync.ts`, and `outlook-com-sync.ts`.
- Added local file attachment picking (`Attach` button) and `multipart/mixed` sending for both newly attached local files and existing remote Gmail draft attachments.
- Clicking any attachment in the Composer or Reading Pane now downloads/caches it to `%TEMP%\everybox-attachments\` and opens it in the default OS application across Gmail, IMAP, and Classic Outlook.
- Added `Cc` and `Bcc` lines under `To` in `ThreadReader.tsx` with hover tooltips and right-click menus.
- Added red `Draft` pills in `ThreadList.tsx`, red-dashed `Unsent Draft` cards with 1-click `Edit & Send` in `ThreadReader.tsx`, and updated `database.ts` Drafts query to include draft replies attached to Inbox threads (`EXISTS (SELECT 1 FROM messages m WHERE m.thread_id = t.id AND m.is_draft = 1)`).

### Decision
- Shipped full end-to-end attachment open/attach/send support across all three providers, `Cc`/`Bcc` display, and inline draft indicators. Left Gmail Templates alone (Google API limitation; user can delete unused templates in Gmail).

### Alternatives Considered
- Heuristic filtering of Gmail drafts to hide templates — rejected because it risks silently hiding real user drafts.

### Action Items
- None; verified with clean `npm run typecheck`, `npm run build`, and live testing.

  4. **Sidebar & Unified Search (`Sidebar.tsx`, `App.tsx`, `ThreadList.tsx`, `useAppStore.ts`):** Promoted **New message (`C`)** to a full-width primary CTA at the top of the sidebar; distinguished **AI Assistant** as a side-panel toggle (`Panel`/`Open`); raised unchecked account contrast to WCAG AA; removed the misleading `1` active-rule-count badge from **Autopilot** (which looked like an unread notification); made top search default to **All accounts** with an inline **`All accounts ▾`** single-account scope toggle and separated `Ctrl+K` outside the input; collapsed `Filter this inbox…` behind a compact filter icon button; changed `SEARCH` → `Search`; reordered row hover actions so `Archive` is leftmost and `Delete` is far right; scaled Undo toast down to `13.5px`; added `focus-visible` rings, `aria-label`s, and a `?` **Keyboard Shortcuts** modal (`ShortcutHelpModal.tsx`).

## 3-Tier Message List Density (`Compact` · `Comfortable` · `Expanded`)
### Context
To let Casey compare "Calm & native Windows" vs. "Softer & more spacious", we initially added a `Calm | Spacious` pill in the top-right title bar. Casey tested it and immediately called it a bust: the pill bled into the Windows minimize/maximize/close caption buttons, and the spacing difference was far too subtle to be useful. Instead, he wanted real, functional inbox list density modes: 1-line (sender only), 2-line (sender + subject), and 3-line (sender + subject + first-line preview).

### Discussion
- Removed `UIFeel` / `data-ui-feel` and the title-bar `Calm | Spacious` pill cleanly across `App.tsx`, `themes.css`, `useAppStore.ts`, `types.ts`, `SettingsModal.tsx`, `ThreadReader.tsx`, and `ThreadList.tsx`.
- Added `ListDensity = 'compact' | 'comfortable' | 'expanded'` to `AppSettings` (default `'expanded'`).
- Placed a 1-click **List density** icon button (`AlignJustify` / `Rows2` / `Rows3`) right in the `ThreadList` header next to the Filter icon (contextual, right above the list it controls, zero title-bar collision), mirrored in **Settings › Appearance › Message List Density**.

### Decision
- Shipped 3 genuinely distinct inbox list modes: **Compact** (1 line, sender + right-aligned timestamp/badges + `24px` avatar), **Comfortable** (2 lines, sender + subject), and **Expanded** (3 lines, sender + subject + snippet preview).

### Alternatives Considered
- Keeping a subtle spacing/shadow toggle in the title bar — rejected as low-value and colliding with Windows caption buttons.

### Action Items
- None; verified and live.
