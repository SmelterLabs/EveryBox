# EveryBox Journal — 2026-11-25

## Classic Outlook Desktop (`outlook-local`) Sync, Focused Inbox Filter & Incremental Speedup
### Context
Casey needed his UNICOM Microsoft 365 Exchange account connected in EveryBox without OAuth admin-consent workarounds, and wanted Outlook's Focused/Other classification respected so spammy "Other" mail stays out of EveryBox. After connecting Classic Outlook Desktop via COM/MAPI, two issues surfaced: emails deleted in Outlook Webmail stayed in EveryBox's Inbox, and UNICOM syncs took ~60–90 seconds per poll (causing `Sync now` clicks during an in-flight sync to be ignored).

### Discussion
- Classic Outlook Desktop sign-in initially failed due to `HKCU:\Software\Microsoft\Office\16.0\Outlook\AutoDiscover\ExcludeExplicitO365Endpoint = 1`; flipping it to `0` unblocked Exchange login cleanly.
- `syncOutlookComAccount` in `src/main/mail/outlook-com-sync.ts` only upserted items and never called `db.reconcileFolderMessages`, unlike Gmail and IMAP.
- Each poll was re-reading full `HTMLBody`, `Body`, `Recipients`, and headers over COM for 360 emails (80 Inbox + 160 Sent + 30 each of Drafts/Junk/Trash/Archive) plus walking 100+ Exchange subfolders every minute.

### Decision
- Added per-account `outlookFocusedMode` (`focused-only` / `other-to-updates` / `all`) using MAPI proptag `0x12130003` (`1` = Other) + header fallback.
- Added windowed `db.reconcileFolderMessages` for `inbox`, `drafts`, `junk`, `trash`, and `archive` so deletions and moves in Outlook Webmail / mobile clear out of EveryBox automatically.
- Made `syncOutlookComAccount` incremental: passes known `remote_id`s to PowerShell via temp file, skips body/recipient/header COM reads for already-cached EntryIDs (updating only read/star flags via `db.updateLocalMessageFlagsByRemoteId` plus Focused/Other and reconciliation), tightens incremental limits (`60` Inbox, `25` Sent, `15` Drafts/Junk/Trash), and throttles the custom subfolder tree walk to once every 10 minutes.

### Alternatives Considered
- Full polling every 60s without caching — too slow (~60–90s), causing constant `syncing` state.
- Tightening poll cadence to 30s or adding IMAP IDLE — deferred for later per Casey ("we don't have to worry about it yet. We can tweak that later").

### Action Items
- None immediate; optional sync cadence / IMAP IDLE tuning tracked in `current-work.md`.

## Autopilot Background AI Pre-Drafts Tuning & "Always Auto-Draft" VIP Senders
### Context
Background AI Pre-Drafts were drafting replies to Amazon order confirmations and newsletters. An initial strict fix added a `isKnownHuman` correspondence gate (only replies, known contacts, and same-company colleagues), which Casey felt went too far because first-time human emails should still be eligible. Meanwhile, he wanted a way right inside the AI draft box to mark a sender as "Always auto-draft."

### Discussion
- Kept all zero-AI-cost automated filters (`automatedSenderRe`, `automatedSubjectRe`, `unsubscribeUrl`, `signInCode`, `category !== 'people'`, and full-body `unsubscribe` / `manage preferences` / `view in browser` / `opt out` checks) plus bulk purge of all existing pre-drafts from a sender when muted (`deletePreDraftsBySender`).
- Removed the `isKnownHuman` positive gate so new human senders remain eligible.
- Added `preDraftAlwaysSenders?: string[]` to `AutopilotSettings`: VIP senders run first (up to 4 per pass), bypass automated/category/footer heuristics, and continue running even if the blanket `autoPreDraftPeople` toggle is turned off.

### Decision
- Added **Always auto-draft for this sender** toggle directly in the **AI Draft Ready** card (`ThreadReader.tsx`) and the **Composer** AI bar (`Composer.tsx`), manageable as removable pills in `AutopilotView.tsx` and removable from `ThreadList.tsx` right-click menu.

### Alternatives Considered

## Search, Folder Filing, Replied Thread Display & Sync/Drafts Reliability Fixes
### Context
Live daily use across 6 accounts surfaced several subtle email-client edge cases:
1. Multi-select Delete in Search results appeared to only unselect items because `searchThreads` (and Starred/All/Custom views) didn't exclude `trash`/`junk`.
2. Top search ignored the left-pane single-account focus filter, lacked `X` clear buttons, and didn't show which folder each search result lived in.
3. Right-click `Move to` cut off at 12 folders and couldn't scroll; top email action icons needed to be slightly larger (`28px`) and needed a `Move to folder` button.
4. Replied threads in Inbox showed Casey's own name/initials and jumped to the top of Today using his outgoing reply timestamp instead of when the incoming email arrived.
5. Deleted emails occasionally resurrected 5–8 seconds later due to an in-flight background sync overwriting `trash` back to `inbox` from a stale snapshot.
6. Sending a Draft from Drafts left the original draft sitting in Drafts (and showed the `↩` Replied icon), because `openComposer` dropped `draftThreadId`/`draftRemoteId`, Gmail sync didn't reconcile `DRAFT`, and `queueSendWithUndo` shared a single `pendingSendTimer` that cancelled earlier sends on rapid-fire sending.

### Discussion & Decisions
- **Search & Folders:** Top search now follows `activeAccountIds` with a 1-click `Search all accounts` link; both search bars have `X` clear buttons + `Esc`; Search/Starred/Waiting rows show compact folder pills (`Inbox`, `Sent`, `Archive`, subfolder names, red-tinted `Trash`/`Junk`); Search excludes Trash/Junk by default with a 1-click `Include Trash & Junk` toggle.
- **Move & Actions:** Removed the 12-folder slice in `ThreadList.tsx`; made `ContextMenu.tsx` submenus viewport-clamped, scrollable, and filterable (>10 items); bumped top email action icons in `ThreadReader.tsx` to `28px` and added a searchable **Move to folder** dropdown.
- **Archive vs. Delete:** Decided to keep Archive in EveryBox for public Gmail/Superhuman users even though Casey files into Inbox subfolders instead.
- **Replied Threads:** Inbox and folder views now project `latestExternalFrom` and `received_date` (`is_sent = 0`) in `database.ts`, showing the correspondent's name/avatar, an accent `↩` Replied icon, `You:` snippet prefix, fixed `Reply to <correspondent>…` quick-reply bar, and original received timestamp/sort position (while Sent remains sorted by sent time).
- **Zombie Email Race Fix:** Added a 90-second `recentMutations` + `recentDeletedRemoteIds` guard in `database.ts` (`upsertMessageAndThread` and `reconcileFolderMessages`), paused background polls during in-flight remote mutations in `sync-manager.ts`, and grouped IMAP UID mutations by each message's actual source folder.
- **Drafts Send & Cleanup:** Wired `draftThreadId` + `draftRemoteId` through `openComposer` → `Composer` → `SyncManager.sendEmail` → `deleteGmailDraftByMessageId` (plus IMAP/Outlook delete + immediate local delete); added Gmail `DRAFT` reconciliation in `gmail-sync.ts`; removed `↩`/`You:` from Drafts; gave each queued Undo Send its own independent timer in `useAppStore.ts`.

### Alternatives Considered
- Inline expandable thread tree in the middle list (Outlook style) — rejected in favor of keeping the full thread in the right reading pane with `↩` + message count in the list for cleaner scanning and multi-select.
- Removing Archive UI globally — rejected to preserve public-app compatibility for Inbox Zero / Gmail users.

### Action Items
- None; all verified with clean `npm run typecheck`, `npm run build`, and live testing in EveryBox.
